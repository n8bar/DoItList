# m04.02 — Client-Owned Tree
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Approved 2026-09-15_

## Goal

Move the Initiative tree model, rendering, and interaction response into the browser while preserving existing product behavior.

## Worklists

1. [x] **Normalized tree model** — stable Task ids stay separate from positional labels; only structurally stale labels recompute.
   1. [x] Load Task records, child order, references, and roll-up display truth without retaining the nested snapshot as mutable state.
      1. [x] Add `co_assignee_ids`, `comment_count`, `cross_references`, and `referenced_by` to `TaskNode` in `assets/js/client/api/types.ts`.
      2. [x] Add `assets/js/client/tree/model.ts` holding `tasks` by id, `childIds` by parent id, and the root id, built by `fromSnapshot` from the nested read.
      3. [x] Keep the server's `progress`, `index`, and `depth` on each record as display truth; the nested `tasks` array is dropped after flattening.
      4. [x] Add `assets/js/client/tree/labels.ts` porting `DoIt.Tasks.Index.label/2` for all five styles, recomputing only the sibling run whose positions changed and its subtrees.
      5. [x] Store the model per Initiative in `stores.domain` in place of `initiativeTrees`.
   2. [x] Load Initiative metadata, membership, and permissions into separate typed state.
      1. [x] Add `GET /app/api/initiatives/:id/members` through the shared `DoItWeb.Api.Reads`, with `require_agent_access: false`.
      2. [x] Add `InitiativeMeta` (name, subtitle, role, progress_calc, index_style, root_task_id, version) and `members` as their own fields in `stores.domain`.
      3. [x] Derive `permissions` (`canEdit`, `canAdmin`, `viewerPlus`) from role in a pure module; nothing renders from the raw role string.
   3. [x] Provide pure model operations for add, update, completion, and delete/restore.
      1. [x] Add `assets/js/client/tree/ops.ts` where every operation returns a new model plus the affected task ids.
      2. [x] Port `DoIt.Tasks.Progress` (leaf average, single level, rounding) to `assets/js/client/tree/progress.ts` for display-only prediction of the affected lineage.
      3. [x] Implement `addTask` with the placement defaults of ProductSpec §10.8 and a negative temporary id until the server id arrives.
      4. [x] Implement `updateFields` for title, description, priority, assignee, co-assignees, and manual progress.
      5. [x] Implement `setDone` mirroring `cascade_complete` / `cascade_incomplete`, including un-doing done ancestors.
      6. [x] Implement `deleteSubtree` and `restoreSubtree` as soft removal and reinsertion at the recorded position.
   4. [x] Provide pure model operations for move, reorder, and sort.
      1. [x] Implement `moveTask` with `Tasks.move_task/3` semantics: same Initiative, no cycle, reparent lands at the top unless `reorder`, root bottom zone appends.
      2. [x] Port `DoIt.Tasks.Sort.apply/3` comparators and `resolve_sort` inheritance to `assets/js/client/tree/sort.ts`.
      3. [x] Implement `reorderSiblings` pinning the parent to manual sort, and `setSort` / `cascadeSort` re-sorting the affected branches.
   5. [x] Apply canonical deltas through a pure model operation.
      1. [x] Add `assets/js/client/tree/delta.ts` with `applyDelta(model, {upserts, removed, initiative})` as the only way canonical records enter the model.
      2. [x] Map an operations result (`task_result` shape) and a full snapshot onto that delta so acknowledgement, refetch, and the Arc 3 envelope share one path.
   6. [x] Validate malformed snapshots and impossible trees into an explicit resync/error path.
      1. [x] Add `assets/js/client/tree/validate.ts` checking known parents, one root, no cycles, unique ids, and contiguous positions.
      2. [x] On failure, refetch once; a second failure raises a recovery notice instead of rendering a partial tree.

2. [x] **Omissions and Corrections** — features and fixes that should have been in previous milestones and arcs.
   1. [x] **Multi-task move** — one op moves an ordered list of Tasks under one parent; one undo entry, one activity line, one broadcast.
      1. [x] Add `Tasks.move_tasks/3`: an ordered list of Tasks, a parent, and an optional position; siblings land in list order; one `moved_many` event that undo reverses as a whole.
      2. [x] Accept `ids` on `update task` in `DoItWeb.Api.Operations`, calling `Tasks.move_tasks/3`; the result carries every moved record.
      3. [x] Let the `move_task` tool and the CLI `move` verb take many Tasks; one Task still works as today.
      4. [x] Add one line to `skills/doitlist/SKILL.md` under Lanes: several moves to the same parent are one `move`, never one call each.
      5. [x] Write the prose entry in `agent_surfaces.md`.
   2. [x] **Respect the order** — Multi-task moves are ignoring the id list order and moving in willy nilly. Fix it.

3. [x] **Rendering parity** — preserve layout, themes, motion, touch, keyboard, focus, accessibility, and local-only view behavior.
   1. [x] Render task-row content, progress, references, and assignees from client state.
      1. [x] Add `assets/js/client/tree/row.tsx` reproducing `task_node/1`'s markup and classes so the existing `app.css` rules style both trees.
      2. [x] Render label, wrapped title, priority, checkbox and progress bar, leaf / child counts, and the personal row preferences.
      3. [x] Render reference chips by importing the existing `assets/js/refs.js` parser rather than a second copy.
      4. [x] Render assignee and co-assignee avatars from `members`.
   2. [x] Render the hierarchy, add forms, and selection from client state.
      1. [x] Add `assets/js/client/tree/tree.tsx` rendering nested lists from `childIds`, keyed by task id.
      2. [x] Keep expand/collapse in the existing `phx:collapse:<initiative>:<task>` local key so a branch's open state never depends on its child count.
      3. [x] Drive selection through `ui.selectedTaskId` and the `task` deep-link parameter; a selection change never waits on the network.
      4. [x] Port the keyboard model (arrows, Enter, Escape, priority/assignee step, shortcut overlay) to a pure `tree/keyboard_model.ts`.
      5. [x] Render **+ New Sibling** and **+ New Subtask** forms at the invoking position with focus in the title field.
      6. [x] Preserve readable width, horizontal scroll, uniform top-level width, and title wrapping per ProductSpec §6.2.
   3. [x] Render drag/drop bands from client state.
      1. [x] Port `bandFor`, `siblingPosition`, the branch tail zone, and the root top/bottom overlays to a pure `tree/drag_model.ts`.
      2. [x] Add `tree/drag.tsx` driving the gesture with pointer events (mouse, pen, touch) and a placeholder at the destination.
      3. [x] Show overlays only while a drag is active; hold the dragged row in place until the move is acknowledged.
   4. [x] Render presence and the Details-pane seed from client state.
      1. [x] Track selection presence in `DoItWeb.InitiativeChannel` with `DoItWeb.Presence`; accept a `select` push and send `presence_state` / `presence_diff` to members.
      2. [x] Hold other members' selections and online ids in client state and paint row badges and online dots from it.
      3. [x] Open the Details pane on selection with the task's editable fields from the model; comments, activity, and chat remain Arc 7.

4. [x] **Initiatives index parity** — the page is the M02 page, built against its LiveView template, not the Arc 1 stand-in.
   1. [x] Port the page header: the "My Initiatives" title, its tagline, and New Initiative.
   2. [x] Port the Sort control and Reverse.
   3. [x] Port the card: name, role badge, updated date, description, and the progress bar with its percent on the bar.
   4. [x] Port dragging to reorder.
   5. [x] Port the Archived and Trash footer, the hidden and trash views, and unarchive.
   6. [x] Apply live list changes without refetching the page.

5. [x] **Optimistic operation adapter** — server truth stays authoritative; prediction is display-only; existing decision, failure, undo, and redo behavior remains intact.
   1. [x] Route every existing tree write through one client operation adapter with a stable idempotency key and the existing atomic operation shape.
      1. [x] Add `assets/js/client/tree/adapter.ts`: an intent becomes one batch with a generated key, submitted in creation order per Initiative.
      2. [x] Add an undo/redo operation to `DoItWeb.Api.Operations` calling `Tasks.undo/2` / `Tasks.redo/2`, with the affected task records in its result.
      3. [x] Send field edits with only the changed fields and the record's `expected_version`.
      4. [x] Open cascade-complete, completion-flip, and cascade-sort confirms from the model before submitting; honor the existing per-class "don't ask again" key.
      5. [x] Accept `sort_mode`/`sort_reverse` and `cascade_sort` on `update task` in `DoItWeb.Api.Operations`, calling `Tasks.set_sort/4` / `cascade_sort/2`, with prose in `agent_surfaces.md`.
   2. [x] Apply known outcomes locally, mark exactly the affected scope pending, and reconcile canonical success without flicker.
      1. [x] Keep `pending` (saving and recomputing ids) in ephemeral state, set from the operation's affected ids.
      2. [x] On success apply the result delta and clear pending; rows keep their keys so nothing remounts.
      3. [x] On rejection revert structural intent to canonical state and keep rejected text recoverable in the field with the error beside it.

6. [x] **Tree correctness** — empty moved-from branches stay open at 0%; branch tail drop-zones stay last.
   1. [x] Remove equivalent obsolete DOM-patch and predictor paths rather than leaving two behaviors alive.
      1. [x] Inside the client, prediction comes only from the model; no DOM-reading predictor or `rollup.js` import is added.
      2. [x] The LiveView tree and its `app.js` predictors stay until Arc 7 retires that route.

## Exit

The browser owns the complete tree experience and submits through one operation adapter; the server no longer renders or patches task rows.
