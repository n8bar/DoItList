# m04.02 — Client-Owned Tree
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Approved 2026-09-15_

## Goal

Move the Initiative tree model, rendering, and interaction response into the browser while preserving existing product behavior.

## Worklists

1. [ ] **Normalized tree model** — stable Task ids stay separate from positional labels; only structurally stale labels recompute.
   1. [ ] Load Task records, child order, references, and roll-up display truth without retaining the nested snapshot as mutable state.
   2. [ ] Load Initiative metadata, membership, and permissions into separate typed state.
   3. [ ] Provide pure model operations for add, update, completion, and delete/restore.
   4. [ ] Provide pure model operations for move, reorder, and sort.
   5. [ ] Apply canonical deltas through a pure model operation.
   6. [ ] Validate malformed snapshots and impossible trees into an explicit resync/error path.

2. [ ] **Rendering parity** — preserve layout, themes, motion, touch, keyboard, focus, accessibility, and local-only view behavior.
   1. [ ] Render task-row content, progress, references, and assignees from client state.
   2. [ ] Render the hierarchy, add forms, and selection from client state.
   3. [ ] Render drag/drop bands from client state.
   4. [ ] Render presence and the Details-pane seed from client state.

3. [ ] **Optimistic operation adapter** — server truth stays authoritative; prediction is display-only; existing decision, failure, undo, and redo behavior remains intact.
   1. [ ] Route every existing tree write through one client operation adapter with a stable idempotency key and the existing atomic operation shape.
   2. [ ] Apply known outcomes locally, mark exactly the affected scope pending, and reconcile canonical success without flicker.

4. [ ] **Tree correctness** — empty moved-from branches stay open at 0%; branch tail drop-zones stay last.
   1. [ ] Remove equivalent obsolete DOM-patch and predictor paths rather than leaving two behaviors alive.

5. [ ] **Testing**
   1. [ ] [Agent] Unit-test pure content, lifecycle, structure, ordering, and delta operations.
   2. [ ] [Agent] Property-test no cycles, stable ids, ordered siblings, one parent, valid labels, and deterministic delta application.
   3. [ ] [Agent] Run browser coverage for add, edit, completion, confirms, delete, undo, and redo.
   4. [ ] [Agent] Run browser coverage for move, reorder, sort, and drag/drop bands.
   5. [ ] [Agent] Run browser coverage for selection, panes, references, presence, and deep links.
   6. [ ] [Agent] Test readable width, title wrapping, horizontal and pane scrolling, responsive panes, themes, touch targets, and reduced motion.
   7. [ ] [Agent] Test keyboard selection, shortcuts, add placement, reorganization, deep-link reveal, focus/caret, and screen-reader context.
   8. [ ] [Agent] Verify view-only actions remain local before connection, during ordinary operation, and through rerender.
   9. [ ] [Agent] Test display-only roll-up prediction, canonical replacement, confirmations, cancellation, failure, undo, and redo.
   10. [ ] [Agent] Verify empty moved-from branches and branch tail drop-zones satisfy the Tree correctness constraints.
   11. [ ] [Agent] Verify every tree action meets `UX_GUARDRAILS.md` §6 under the ratified latency profile and works from first paint where client-ownable.
   12. [ ] [Agent] Confirm every endpoint, operation, or field added here has current prose in [`agent_surfaces.md`](../../reference/agent_surfaces.md).
   13. [ ] [Human] Compare representative small and deep Initiatives against the current interface in desktop and narrow layouts, light and dark.

## Exit

The browser owns the complete tree experience and submits through one operation adapter; the server no longer renders or patches task rows.
