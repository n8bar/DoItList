# m04.02 — Client-Owned Tree
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Goal approved 2026-09-15 · Worklists unapproved_

## Goal

Move the Initiative tree model, rendering, and interaction response into the browser while preserving existing product behavior.

## Worklists

1. [ ] **Normalized tree model**
   1. [ ] Load Task records, child order, references, and roll-up display truth without retaining the nested snapshot as mutable state.
   2. [ ] Load Initiative metadata, membership, and permissions into separate typed state.
   3. [ ] Provide pure model operations for add, update, completion, and delete/restore.
   4. [ ] Provide pure model operations for move, reorder, and sort.
   5. [ ] Apply canonical deltas through a pure model operation.
   6. [ ] Keep stable Task ids distinct from positional labels and recompute labels only where structure makes them stale.
   7. [ ] Validate malformed snapshots and impossible trees into an explicit resync/error path.

2. [ ] **Rendering parity**
   1. [ ] Render task-row content, progress, references, and assignees from client state.
   2. [ ] Render the hierarchy, add forms, and selection from client state.
   3. [ ] Render drag/drop bands from client state.
   4. [ ] Render presence and the Details-pane seed from client state.
   5. [ ] Preserve readable width, wrapping titles, horizontal scroll, responsive panes, and independent scrolling.
   6. [ ] Preserve themes, touch targets, and reduced motion.
   7. [ ] Preserve keyboard selection, shortcuts, add placement, and reorganization.
   8. [ ] Preserve deep-link reveal, focus/caret, and screen-reader context.
   9. [ ] Keep all view-only actions local before connection, during ordinary operation, and through rerender.

3. [ ] **Optimistic operation adapter**
   1. [ ] Route every existing tree write through one client operation adapter with a stable idempotency key and the existing atomic operation shape.
   2. [ ] Apply known outcomes locally, mark exactly the affected scope pending, and reconcile canonical success without flicker.
   3. [ ] Preserve server-authored roll-up truth while retaining the current display-only local prediction for the acting user's immediate feedback.
   4. [ ] Keep confirmation, cancellation, and failure semantics intact across optimistic structural and completion actions.
   5. [ ] Keep undo and redo semantics intact across optimistic structural and completion actions.

4. [ ] **Tree correctness**
   1. [ ] Emptying a branch through a move does not predict false completion; the empty branch stays open at 0%.
   2. [ ] A branch tail drop-zone remains the branch's bottom element through optimistic placement and canonical acknowledgement.
   3. [ ] Remove equivalent obsolete DOM-patch and predictor paths rather than leaving two behaviors alive.

5. [ ] **Testing**
   1. [ ] [Agent] Unit-test pure content, lifecycle, structure, ordering, and delta operations.
   2. [ ] [Agent] Property-test no cycles, stable ids, ordered siblings, one parent, valid labels, and deterministic delta application.
   3. [ ] [Agent] Run browser coverage for add, edit, completion, confirms, delete, undo, and redo.
   4. [ ] [Agent] Run browser coverage for move, reorder, sort, and drag/drop bands.
   5. [ ] [Agent] Run browser coverage for selection, panes, references, presence, and deep links.
   6. [ ] [Agent] Verify every tree action meets `UX_GUARDRAILS.md` §6 under the ratified latency profile and works from first paint where client-ownable.
   7. [ ] [Agent] Confirm every endpoint, operation, or field added here has current prose in [`agent_surfaces.md`](../../reference/agent_surfaces.md).
   8. [ ] [Human] Compare representative small and deep Initiatives against the current interface in desktop and narrow layouts, light and dark.

## Exit

The browser owns the complete tree experience and submits through one operation adapter; the server no longer renders or patches task rows.
