# m04.03 — Live Sync & Recovery
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Goal approved 2026-09-15 · Worklists unapproved_

## Goal

Make accepted and pending work survive ordinary collaboration, lost connections, reloads, crashes, duplicates, gaps, and rejected writes without silent loss.

## Worklists

1. [ ] **Ordered canonical delivery**
   1. [ ] Add the monotonic Initiative sequence and advance it in the same transaction as each durable Initiative mutation.
   2. [ ] Emit one post-commit canonical delta envelope carrying the sequence, origin key, actor, and sufficient changed/removed records.
   3. [ ] Deliver deltas over an authenticated Initiative channel with membership checked on join and on live membership change.
   4. [ ] Deduplicate own acknowledgement versus broadcast, ignore old delivery, apply consecutive delivery once, and resnapshot on a gap.

2. [ ] **Durable pending queue and snapshot cache**
   1. [ ] Persist each operation and its recovery data in IndexedDB before it can be forgotten by memory, navigation, reload, or tab crash.
   2. [ ] Persist the last-known canonical Initiative snapshot and sequence with bounded age/size and account isolation.
   3. [ ] Replay per-client intent in creation order; preserve atomic batches and reuse the original idempotency key after unknown outcomes.
   4. [ ] Purge on logout or access loss, warning before logout when pending work exists.

3. [ ] **Race-free resynchronization**
   1. [ ] Subscribe and buffer before snapshot installation; apply only buffered deltas newer than the snapshot sequence.
   2. [ ] Reconcile pending intent over canonical state, replay it, and converge without a duplicate, missing operation, or visible snap.
   3. [ ] Make repeated resync idempotent and bound retries, buffers, and retained recovery data.
   4. [ ] Cover navigation between Initiatives so late messages or cached state can never cross the Initiative boundary.

4. [ ] **Concurrent intent and rejection**
   1. [ ] Show short-lived editing presence for focused fields; warn without blocking when another user focuses the same field.
   2. [ ] On a remote write, update an untouched focused field; for a dirty field, show both values and an overwrite warning while keeping normal blur-save.
   3. [ ] Show Cancel inside a dirty field only while a remote value is waiting; Cancel discards the draft and adopts that value.
   4. [ ] Implement field-level rebase and bounded retry on stale versions without erasing unrelated fields.
   5. [ ] Re-evaluate stable-anchor move/reorder intent against current structure and reject impossible outcomes visibly.
   6. [ ] Revert rejected structural optimism; keep rejected editable content recoverable with Retry and Discard actions.
   7. [ ] Apply live role/access loss immediately and stop unauthorized replay.

5. [ ] **Degraded mode**
   1. [ ] Implement connecting, live, reconnecting, offline, pending-offline, and unrecoverable states with local and global signifiers.
   2. [ ] Keep last-known content readable and client-ownable view actions usable throughout server disturbance.
   3. [ ] Use bounded exponential backoff with jitter, then a clear Retry action and non-strobing low-frequency reachability probe.
   4. [ ] Distinguish safely queueable actions from actions requiring current server facts; never accept an action silently that cannot be honored.

6. [ ] **Testing**
   1. [ ] [Agent] Deterministically test acknowledgement-first and broadcast-first order, duplicates, gaps, out-of-order delivery, snapshot races, dropped replies, and idempotent replay.
   2. [ ] [Agent] Test offline edit → reload/tab crash → reconnect, queue ordering, atomic batches, corrupt IndexedDB, quota failure, logout warning/purge, and access loss.
   3. [ ] [Agent] Test concurrent same-field, different-field, completion, delete/edit, and structural conflicts until every client reaches identical canonical state.
   4. [ ] [Agent] Verify every action and failure meets `UX_GUARDRAILS.md` §6, including both WebSocket and LongPoll fallback.
   5. [ ] [Agent] Confirm every endpoint, operation, or field added here has current prose in [`agent_surfaces.md`](../../reference/agent_surfaces.md).
   6. [ ] [Human] Disconnect during a title edit, reload, reconnect, and confirm the edit stays visible as unsaved until acknowledged and never disappears.

## Exit

The synchronization state machine is deterministic, durable on-device, bounded, observable to the user, and proven against the failure modes that motivated the milestone.
