# m04.03 — Live Sync & Recovery
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Approved 2026-09-15_

## Goal

Make accepted and pending work survive ordinary collaboration, lost connections, reloads, crashes, duplicates, gaps, and rejected writes without silent loss.

## Worklists

1. [x] **Ordered canonical delivery**
   1. [x] Add the monotonic Initiative sequence and advance it in the same transaction as each durable Initiative mutation.
   2. [x] Emit one post-commit canonical delta envelope carrying the sequence, origin key, actor, and sufficient changed/removed records.
   3. [x] Deliver deltas over an authenticated Initiative channel.
      1. [x] Check membership on join.
      2. [x] Recheck membership on live membership change.
   4. [x] Apply ordered delivery safely.
      1. [x] Deduplicate an own-write acknowledgement and broadcast.
      2. [x] Ignore old delivery.
      3. [x] Apply consecutive delivery once.
      4. [x] Resnapshot on a gap.

2. [x] **Durable pending queue and snapshot cache** — retained data stays age/size-bounded and account-isolated.
   1. [x] Persist each operation and its recovery data in IndexedDB before it can be forgotten by memory, navigation, reload, or tab crash.
   2. [x] Persist the last-known canonical Initiative snapshot and sequence.
   3. [x] Replay per-client intent safely.
      1. [x] Replay in creation order.
      2. [x] Preserve atomic batches.
      3. [x] Reuse the original idempotency key after an unknown outcome.
   4. [x] Clear device state at an account boundary.
      1. [x] Warn before logout when pending work exists.
      2. [x] Purge on logout or access loss.

3. [x] **Race-free resynchronization** — gap-free, visually continuous, idempotent, bounded, and Initiative-isolated.
   1. [x] Subscribe and buffer before snapshot installation; apply only buffered deltas newer than the snapshot sequence.
   2. [x] Reconcile after snapshot installation.
      1. [x] Rebase pending intent over canonical state.
      2. [x] Replay the rebased intent.
   3. [x] Resync every joined Initiative from its last sequence whenever the socket reopens, so changes made during an outage never wait for the next live event.

4. [x] **Concurrent intent and rejection** — field rebases never erase unrelated fields.
   1. [x] Provide advisory field-editing presence.
      1. [x] Show short-lived presence for focused fields.
      2. [x] Warn without blocking when another user focuses the same field.
   2. [x] Handle a remote write to a focused field.
      1. [x] Update an untouched field.
      2. [x] For a dirty field, show both values and an overwrite warning while keeping normal blur-save.
   3. [x] Show Cancel inside a dirty field only while a remote value is waiting; Cancel discards the draft and adopts that value.
   4. [x] Implement field-level rebase and bounded retry on stale versions.
   5. [x] Re-evaluate stable-anchor move/reorder intent against current structure and reject impossible outcomes visibly.
   6. [x] Recover rejected optimistic work.
      1. [x] Revert rejected structural optimism.
      2. [x] Keep rejected editable content recoverable with non blocking Retry and Discard actions.
   7. [x] Apply live role/access loss immediately and stop unauthorized replay.

5. [x] **Degraded mode** — last-known content and local view actions remain usable; unavailable actions never disappear silently.
   1. [x] Implement the degraded connection state model.
      1. [x] Implement connecting, live, and reconnecting states.
      2. [x] Implement offline, pending-offline, and unrecoverable states.
      3. [x] Provide local and global signifiers for every state.
   2. [x] Provide bounded reconnection.
      1. [x] Use exponential backoff with jitter.
      2. [x] End automatic retries with a clear Retry action.
      3. [x] Probe reachability at a low, non-strobing frequency.
   3. [x] Classify safely queueable actions and actions requiring current server facts.

6. [ ] **Testing**
   1. [x] [Agent] Deterministically test ordered delivery and resynchronization.
      1. [x] [Agent] Test acknowledgement-first, broadcast-first, duplicate, old, and out-of-order delivery.
      2. [x] [Agent] Test gaps and snapshot races.
      3. [x] [Agent] Test dropped replies and idempotent replay.
   2. [x] [Agent] Test durable recovery.
      1. [x] [Agent] Test offline edit → reload/tab crash → reconnect.
      2. [x] [Agent] Test queue ordering and atomic batches.
      3. [x] [Agent] Test corrupt IndexedDB and quota failure.
      4. [x] [Agent] Test logout warning/purge and access loss.
   3. [x] [Agent] Test collaboration conflicts until every client reaches identical canonical state.
      1. [x] [Agent] Test same-field and different-field edits.
      2. [x] [Agent] Test completion and delete/edit conflicts.
      3. [x] [Agent] Test structural conflicts.
   4. [x] [Agent] Test repeated resync remains idempotent, bounded, gap-free, visually continuous, and Initiative-isolated.
   5. [x] [Agent] Test stale field rebases preserve unrelated fields.
   6. [x] [Agent] Test last-known content and local view actions remain usable while server-dependent actions fail visibly.
   7. [x] [Agent] Verify every action and failure meets `UX_GUARDRAILS.md` §6, including both WebSocket and LongPoll fallback.
   8. [x] [Agent] Confirm every endpoint, operation, or field added here has current prose in [`agent_surfaces.md`](../../reference/agent_surfaces.md).
   9. [ ] [Human] Disconnect during a title edit, reload, reconnect, and confirm the edit stays visible as unsaved until acknowledged and never disappears.

## Exit

The synchronization state machine is deterministic, durable on-device, bounded, observable to the user, and proven against the failure modes that motivated the milestone.
