# m04.06 — Tree Tools & View Controls
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Goal approved 2026-09-15 · Worklists unapproved_

## Goal

Give people immediate, understandable control over tree expansion, filtering, and row presentation on the client-owned renderer.

## Worklists

1. [ ] **Navigation controls look actionable**
   1. [ ] Style Tree Tools, View, Assigned to Me, and adjacent navigation actions as unmistakable buttons with visible boundaries.
   2. [ ] Provide clear hover, keyboard focus, pressed/open, active-filter, and disabled states in light and dark themes.
   3. [ ] Keep labels readable, touch targets at least 44×44 px, menus keyboard-operable, and opening/closing free of layout shift.

2. [ ] **Tree Tools**
   1. [ ] Implement Expand all and Collapse all.
   2. [ ] Implement Collapse completed branches and Expand incomplete branches.
   3. [ ] Implement Expand selected subtree and Collapse selected subtree; disable them when no applicable branch is selected.
   4. [ ] Apply every tool to local view state in one acknowledgement, with no server request and no mass row mount.
   5. [ ] Preserve the result across rerender/reconnect using the existing per-browser collapse-state lifetime.

3. [ ] **In-context row display**
   1. [ ] Expose the existing personal Priority, Assignee, Checkbox & progress bar, and Leaf / child count choices in a View menu on the Initiative workspace.
   2. [ ] Apply each choice locally before persisting it through the existing account preference path.
   3. [ ] Keep Account preferences and the in-context View menu synchronized across navigation, reload, and another open session.
   4. [ ] Ensure hiding an element cannot remove the selected Task, title, error/pending state, or the way back to the View menu.

4. [ ] **Hide completed Tasks**
   1. [ ] Add a per-browser, per-Initiative toggle that filters fully completed Tasks from the visible projection without changing roll-up.
   2. [ ] Keep its active state conspicuous in the closed menu and next to the filtered tree so Tasks never appear silently missing.
   3. [ ] Define ancestor visibility so an incomplete path stays understandable and an explicitly selected/deep-linked Task can be revealed.
   4. [ ] Make live completion changes enter or leave the filtered view without scroll jumps or lost focus.

5. [ ] **Descriptions below progress**
   1. [ ] Add an Initiative-level setting that places Task descriptions beneath progress bars for every member; compact presentation remains the default.
   2. [ ] Apply the change immediately for the initiator, broadcast it live, and preserve title wrapping, row measurement, windowed scrolling, and narrow layouts.
   3. [ ] Expose the setting through the operations/API surface and account for it in snapshot and delta serialization.

6. [ ] **Testing**
   1. [ ] [Agent] Test every tool and view setting against selection, filters, collapse persistence, live deltas, reconnect, large fixtures, and another session.
   2. [ ] [Agent] Test keyboard, focus return, touch sizing, accessible names/states, reduced motion, themes, and no layout shift for buttons and menus.
   3. [ ] [Agent] Verify every control acknowledges immediately under `UX_GUARDRAILS.md` §6 and view-only actions make no network request.
   4. [ ] [Agent] Confirm the description field/operation and every other added surface have current prose in [`agent_surfaces.md`](../../reference/agent_surfaces.md).
   5. [ ] [Human] Confirm navigation actions look like buttons, filtered Tasks never feel lost, and row combinations remain readable on phone, laptop, and wide desktop.

## Exit

Tree-wide and row-display controls are instant, visibly reversible, accessible, and cheap on large Initiatives.
