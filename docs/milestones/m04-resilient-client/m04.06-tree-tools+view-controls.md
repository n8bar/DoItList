# m04.06 — Tree Tools & View Controls
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Approved 2026-09-15_

## Goal

Give people immediate, understandable control over tree expansion, filtering, and row presentation on the client-owned renderer.

## Worklists

1. [ ] **Navigation controls look actionable** — labels stay readable, touch targets are at least 44×44 px, menus remain keyboard-operable, and opening/closing causes no layout shift.
   1. [ ] Style Tree Tools, View, Assigned to Me, and adjacent navigation actions as unmistakable buttons with visible boundaries.
   2. [ ] Provide clear interaction states in light and dark themes.
      1. [ ] Style hover and keyboard focus.
      2. [ ] Style pressed/open and active-filter states.
      3. [ ] Style disabled states.

2. [ ] **Tree Tools** — every tool updates local view state in one acknowledgement, with no server request or mass row mount.
   1. [ ] Implement Expand all and Collapse all.
   2. [ ] Implement Collapse completed branches and Expand incomplete branches.
   3. [ ] Implement Expand selected subtree and Collapse selected subtree; disable them when no applicable branch is selected.
   4. [ ] Restore the result after rerender or reconnect from the existing per-browser collapse state.

3. [ ] **In-context row display** — hiding an element never removes the selected Task, title, error/pending state, or way back to the View menu.
   1. [ ] Expose the existing personal Priority, Assignee, Checkbox & progress bar, and Leaf / child count choices in a View menu on the Initiative workspace.
   2. [ ] Apply each choice locally before persisting it through the existing account preference path.
   3. [ ] Synchronize Account preferences and the in-context View menu.
      1. [ ] Restore the same choices after navigation or reload.
      2. [ ] Apply preference changes from another open session.

4. [ ] **Hide completed Tasks**
   1. [ ] Add a per-browser, per-Initiative toggle that filters fully completed Tasks from the visible projection without changing roll-up.
   2. [ ] Show its active state in the closed menu and next to the filtered tree so Tasks never appear silently missing.
   3. [ ] Define visibility for hidden Tasks and their context.
      1. [ ] Keep the incomplete ancestor path understandable.
      2. [ ] Reveal an explicitly selected or deep-linked Task.
   4. [ ] Make live completion changes enter or leave the filtered view without scroll jumps or lost focus.

5. [ ] **Descriptions below progress** — title wrapping, row measurement, windowed scrolling, and narrow layouts remain intact.
   1. [ ] Add an Initiative-level setting that places Task descriptions beneath progress bars for every member; compact presentation remains the default.
   2. [ ] Apply and broadcast the setting.
      1. [ ] Apply the change immediately for the initiator.
      2. [ ] Broadcast the change live.
   3. [ ] Expose and serialize the setting.
      1. [ ] Expose it through the operations/API surface.
      2. [ ] Include it in snapshot serialization.
      3. [ ] Include it in delta serialization.

6. [ ] **Testing**
   1. [ ] [Agent] Test every tool and view setting across relevant state.
      1. [ ] [Agent] Test selection, filters, and collapse persistence.
      2. [ ] [Agent] Test live deltas and reconnect.
      3. [ ] [Agent] Test large fixtures and another session.
   2. [ ] [Agent] Test buttons and menus across input, accessibility, and presentation.
      1. [ ] [Agent] Test keyboard operation and focus return.
      2. [ ] [Agent] Test touch sizing and accessible names/states.
      3. [ ] [Agent] Test reduced motion and light/dark themes.
      4. [ ] [Agent] Test opening and closing without layout shift.
   3. [ ] [Agent] Verify every control acknowledges immediately under `UX_GUARDRAILS.md` §6 and view-only actions make no network request or mass row mount.
   4. [ ] [Agent] Confirm the description field/operation and every other added surface have current prose in [`agent_surfaces.md`](../../reference/agent_surfaces.md).
   5. [ ] [Human] Review the controls and row presentation on phone, laptop, and wide desktop.
      1. [ ] [Human] Confirm navigation actions look like buttons.
      2. [ ] [Human] Confirm filtered Tasks never feel lost.
      3. [ ] [Human] Confirm row combinations remain readable.

## Exit

Tree-wide and row-display controls are instant, visibly reversible, accessible, and cheap on large Initiatives.
