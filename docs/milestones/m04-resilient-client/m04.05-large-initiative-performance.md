# m04.05 — Large-Initiative Performance
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Goal approved 2026-09-15 · Worklists unapproved_

## Goal

Keep the browser responsive as an Initiative grows to thousands of Tasks, without laying out hidden rows or rebuilding the whole tree for a local change.

## Worklists

1. [ ] **Visible-row projection**
   1. [ ] Derive one flat visible sequence from the normalized hierarchy, expansion state, and filters.
   2. [ ] Update only affected projection ranges when structure, completion, filters, or expansion changes.
   3. [ ] Keep collapsed and filtered descendants out of layout and accessibility traversal while retaining them in roll-up and whole-tree operations.
   4. [ ] Preserve selection and reveal semantics when the selected Task becomes filtered, collapsed, moved, or deleted.

2. [ ] **Windowed rendering**
   1. [ ] Mount only visible rows plus bounded overscan, including variable-height wrapped titles and responsive widths.
   2. [ ] Preserve stable scroll position through height measurement, expansion, collapse, optimistic movement, canonical reconciliation, and resize.
   3. [ ] Make keyboard navigation, deep links, focus, accessible position/set-size context, drag auto-scroll, and offscreen drop targets work across unmounted rows.
   4. [ ] Ensure Expand all and other whole-tree actions update model state immediately without mounting every Task.

3. [ ] **Incremental derived work**
   1. [ ] Update labels, references, counts, presence, row display, and affected ancestry from deltas rather than rewalking unrelated branches.
   2. [ ] Keep server roll-up truth authoritative and bound any client display prediction to the affected lineage.
   3. [ ] Profile and remove long tasks, forced synchronous layouts, duplicate tree copies, and retained detached rows.

4. [ ] **Large-Initiative gates**
   1. [ ] Build 3,000+ Task deep, wide, and mixed fixtures plus a containerized browser benchmark.
   2. [ ] Record the capped browser profile, scenarios, sample count, report format, and pass/fail thresholds, following [k6 website load-testing guidance](https://grafana.com/docs/k6/latest/testing-guides/load-testing-websites/) and [k6 thresholds](https://grafana.com/docs/k6/latest/using-k6/thresholds/).
   3. [ ] Measure the current implementation and ratify local-interaction, long-task, layout, and memory budgets with the operator before optimization.
   4. [ ] Measure initial usable paint, memory, scroll, selection, ordinary edits, move/reorder, expand/collapse, filtering, deep-link reveal, and sustained mixed interaction.
   5. [ ] Meet the budgets in the capped reference browser profile.
   6. [ ] Commit reproducible before/after reports, traces for corrected bottlenecks, and automated regression thresholds.

5. [ ] **Testing**
   1. [ ] [Agent] Unit- and property-test projection changes, window boundaries, variable heights, selection/reveal, and structure/filter combinations.
   2. [ ] [Agent] Run automated browser benchmarks repeatedly on every required fixture and fail on budget regression.
   3. [ ] [Agent] Verify §6 acknowledgement and keyboard/focus behavior while CPU is throttled and the network is slow or disconnected.
   4. [ ] [Human] Scroll, navigate, expand, filter, edit, and drag through the large fixtures in desktop/narrow and light/dark modes; judge continuity rather than stopwatch timing.

## Exit

A large Initiative performs work proportional to visible and changed content, with accessibility and interaction parity intact.
