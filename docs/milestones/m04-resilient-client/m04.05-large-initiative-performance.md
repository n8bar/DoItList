# m04.05 — Large-Initiative Performance
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Approved 2026-09-15_

## Goal

Keep the browser responsive as an Initiative grows to thousands of Tasks, without laying out hidden rows or rebuilding the whole tree for a local change.

## Worklists

1. [ ] **Visible-row projection**
   1. [ ] Derive one flat visible sequence from the normalized hierarchy, expansion state, and filters.
   2. [ ] Update only affected projection ranges when structure, completion, filters, or expansion changes.
   3. [ ] Exclude collapsed and filtered descendants from layout and accessibility traversal without excluding them from roll-up and whole-tree operations.
   4. [ ] Preserve selection and reveal semantics as the selected Task changes visibility or location.
      1. [ ] Handle a selected Task becoming filtered or collapsed.
      2. [ ] Handle a selected Task being moved or deleted.

2. [ ] **Windowed rendering**
   1. [ ] Mount only visible rows plus bounded overscan, including variable-height wrapped titles and responsive widths.
   2. [ ] Preserve stable scroll position through rendering changes.
      1. [ ] Handle height measurement and resize.
      2. [ ] Handle expansion and collapse.
      3. [ ] Handle optimistic movement and canonical reconciliation.
   3. [ ] Preserve interaction and accessibility across unmounted rows.
      1. [ ] Support keyboard navigation, deep links, and focus.
      2. [ ] Provide accessible position and set-size context.
      3. [ ] Support drag auto-scroll and offscreen drop targets.
   4. [ ] Update model state immediately for Expand all and other whole-tree actions without mounting every Task.

3. [ ] **Incremental derived work** — server roll-up truth remains authoritative and client prediction stays limited to the affected lineage.
   1. [ ] Update derived state from deltas rather than rewalking unrelated branches.
      1. [ ] Update labels and references.
      2. [ ] Update counts and affected ancestry.
      3. [ ] Update presence and row display.
   2. [ ] Profile and remove avoidable browser work.
      1. [ ] Remove long tasks.
      2. [ ] Remove forced synchronous layouts.
      3. [ ] Remove duplicate tree copies.
      4. [ ] Remove retained detached rows.

4. [ ] **Large-Initiative gates**
   1. [ ] Build 3,000+ Task deep, wide, and mixed fixtures plus a containerized browser benchmark.
   2. [ ] Define reproducible browser benchmark runs following [k6 website load-testing guidance](https://grafana.com/docs/k6/latest/testing-guides/load-testing-websites/) and [k6 thresholds](https://grafana.com/docs/k6/latest/using-k6/thresholds/).
      1. [ ] Record the capped browser profile and scenarios.
      2. [ ] Record the sample count and report format.
      3. [ ] Declare pass/fail thresholds.
   3. [ ] Measure the current implementation and ratify local-interaction, long-task, layout, and memory budgets with the operator before optimization.
   4. [ ] Measure the required large-Initiative scenarios.
      1. [ ] Measure initial usable paint and memory.
      2. [ ] Measure scroll and selection.
      3. [ ] Measure ordinary edits and move/reorder.
      4. [ ] Measure expand/collapse, filtering, and deep-link reveal.
      5. [ ] Measure sustained mixed interaction.
   5. [ ] Meet the budgets in the capped reference browser profile.
   6. [ ] Commit reproducible before/after reports, traces for corrected bottlenecks, and automated regression thresholds.

5. [ ] **Testing**
   1. [ ] [Agent] Unit- and property-test projection and windowing.
      1. [ ] [Agent] Test projection changes and window boundaries.
      2. [ ] [Agent] Test variable heights.
      3. [ ] [Agent] Test selection and reveal.
      4. [ ] [Agent] Test structure and filter combinations.
   2. [ ] [Agent] Verify server roll-up remains authoritative and client prediction touches only the affected lineage.
   3. [ ] [Agent] Run automated browser benchmarks repeatedly on every required fixture and fail on budget regression.
   4. [ ] [Agent] Verify §6 acknowledgement and keyboard/focus behavior while CPU is throttled and the network is slow or disconnected.
   5. [ ] [Human] Judge continuity through the large fixtures rather than stopwatch timing.
      1. [ ] [Human] Scroll, navigate, expand, and filter.
      2. [ ] [Human] Edit and drag.
      3. [ ] [Human] Repeat in desktop/narrow and light/dark modes.

## Exit

A large Initiative performs work proportional to visible and changed content, with accessibility and interaction parity intact.
