# m04.01 — Client Runtime
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Approved 2026-09-15_

## Goal

Establish the browser-owned application runtime, authenticated data boundary, and shared interface foundation that every migrated surface uses.

## Worklists

1. [ ] **Client foundation**
   1. [ ] Add React and TypeScript dependencies, manifests, and locked versions inside Docker.
   2. [ ] Configure Phoenix esbuild for TSX and run `tsc --noEmit` for type checking.
   3. [ ] Run pure client tests with `node:test` and include them in precommit.
   4. [ ] Add a direct Brave/Chrome CDP harness that loads the real app and performs one interaction.
   5. [ ] Connect through Phoenix Channels and apply one live update through the production path.

2. [ ] **Bootstrap and session**
   1. [ ] Serve one minimal bootstrap document and production asset entry point without product-shaped server-rendered controls.
   2. [ ] Initialize the signed-in identity and CSRF/session boundary without storing an API bearer token in the browser.
   3. [ ] Show explicit loading, asset-load failure, and client-startup failure states with recovery.
   4. [ ] Show expired-session and forbidden states with appropriate recovery.
   5. [ ] Keep the first-paint theme correct.
   6. [ ] Make the first painted control interactive within the §6 budget.

3. [ ] **State and routing**
   1. [ ] Keep typed domain state, recovery state, preferences, and ephemeral UI state separate.
   2. [ ] Resolve existing paths on direct load and client navigation, preserving deep links and refresh.
   3. [ ] Preserve history, back/forward, scroll, and focus behavior across client routing.
   4. [ ] Add account-scoped IndexedDB with schema versioning and account isolation.
   5. [ ] Bound IndexedDB growth with quota handling and cleanup.
   6. [ ] Purge IndexedDB on logout and recover safely from a corrupt or unavailable store.
   7. [ ] Preserve navigation-level session, subscriptions, and presence continuity.

4. [ ] **Shared interface foundation**
   1. [ ] Implement the application frame, navigation, and rails/panes once for all routes.
   2. [ ] Implement shared dialogs, menus, and forms.
   3. [ ] Implement shared notices, connection summary, and loading/error feedback.
   4. [ ] Preserve responsive, touch, keyboard, theme, reduced-motion, focus-return, and accessible-name behavior from the M02 baseline.
   5. [ ] Make navigation actions visibly button-like, with consistent open, active, pressed, disabled, hover, and focus states.
   6. [ ] Reserve layout space for async content and prevent route or data arrival from shifting established controls.

5. [ ] **Authenticated client data boundary**
   1. [ ] Reuse serializers, authorization, domain contexts, and the operations engine behind session-authenticated browser reads and writes.
   2. [ ] Add only the read/session endpoints or channel calls the inventory proves are missing; do not fork business logic for the browser.
   3. [ ] Standardize success, validation, authorization, stale-session, and transport errors for client consumption.
   4. [ ] Keep browser-private and public agent/API authorization explicit; neither surface gains the other's credentials accidentally.

6. [ ] **Testing**
   1. [ ] [Agent] Test bootstrap, loading/startup failures, session expiry, and forbidden recovery.
   2. [ ] [Agent] Test routing, history, deep links, refresh, scroll, focus restoration, and IndexedDB migration/failure/logout.
   3. [ ] [Agent] Test shared controls, both themes, and narrow/desktop layouts.
   4. [ ] [Agent] Test keyboard, focus, accessible naming, reduced motion, and no-layout-shift behavior for shared primitives.
   5. [ ] [Agent] Verify every action introduced here meets `UX_GUARDRAILS.md` §6 under latency and disconnected startup.
   6. [ ] [Agent] Confirm every endpoint, operation, or field added here has current prose in [`agent_surfaces.md`](../../reference/agent_surfaces.md).
   7. [ ] [Human] Confirm the shell and route transitions look and behave like one product rather than a migration scaffold.

## Exit

The browser runtime can own a route from bootstrap through authenticated reads, writes, errors, navigation, and recovery without LiveView DOM rendering.
