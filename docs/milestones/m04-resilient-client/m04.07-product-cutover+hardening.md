# m04.07 — Product Cutover & Hardening
_Parent: [`m04-resilient-client.md`](m04-resilient-client.md)_
_Status: Approved 2026-09-15_

## Goal

Finish the product-wide client-rendering mandate, remove the old path, and prove the complete product under real interaction, concurrency, and failure conditions.

## Worklists

1. [ ] **Remaining product surfaces** — keep low-frequency surfaces simple while preserving inventoried permissions, confirmations, feedback, deep links, presence, and live updates through the shared runtime, primitives, session boundary, and domain paths.
   1. [ ] Migrate Initiative discovery and personal-work surfaces.
      1. [ ] Migrate Assigned to Me.
      2. [ ] Migrate collaborators and notifications.
   2. [ ] Migrate the remaining account, administration, and collaboration surfaces.
      1. [ ] Migrate account/preferences and authentication/session screens.
      2. [ ] Migrate member management and Initiative settings.
      3. [ ] Migrate import approval.
      4. [ ] Migrate comments, activity, and chat.
      5. [ ] Migrate shared chrome.

2. [ ] **Legacy removal** — domain and protocol coverage remains.
   1. [ ] Complete the client-bootstrap cutover.
      1. [ ] Route all product paths through the client bootstrap.
      2. [ ] Remove interactive LiveView rendering and DOM-patch preservation.
      3. [ ] Remove duplicate hooks and obsolete assigns/events.
   2. [ ] Remove artifacts that only support the retired implementation.
      1. [ ] Remove dead assets and compatibility state.
      2. [ ] Remove tests that only protect the retired implementation.
   3. [ ] Verify no route can accidentally fall back to a stale second interface and no client business rule bypasses server authorization/validation.
   4. [ ] Update documentation for the final boundary.
      1. [ ] Update architecture and development documentation.
      2. [ ] Update troubleshooting and deployment documentation.

3. [ ] **Failure and concurrency matrix**
   1. [ ] Automate the required failure cases.
      1. [ ] Cover slow request, dropped request, and dropped acknowledgement.
      2. [ ] Cover duplicate delta, out-of-order delta, and sequence gap.
      3. [ ] Cover disconnect, reload, and tab crash.
      4. [ ] Cover server restart, deploy, and crash loop.
      5. [ ] Cover reconnect storm and slow-client behavior.
   2. [ ] Automate the required concurrency cases.
      1. [ ] Cover simultaneous field edits and edit/delete.
      2. [ ] Cover completion/move.
      3. [ ] Cover permission change and membership removal.
      4. [ ] Cover Initiative switch and logout with pending work.
   3. [ ] Prove each case has immediate acknowledgement, bounded resource use, no duplicate accepted work, no silent pending-work loss, correct authorization, and eventual convergence or a clear terminal outcome.
   4. [ ] Run the matrix over WebSocket and LongPoll where the transport can change behavior.

4. [ ] **Whole-product quality gate**
   1. [ ] [Agent] Run every required suite from clean containers.
      1. [ ] [Agent] Run unit and property suites.
      2. [ ] [Agent] Run integration and browser suites.
      3. [ ] [Agent] Run accessibility and security suites.
      4. [ ] [Agent] Run performance, load, and soak suites.
      5. [ ] [Agent] Run failure suites.
   2. [ ] [Agent] Re-run all approved capacity and large-Initiative profiles against fixed budgets and publish the final comparison and supported envelope.
   3. [ ] [Agent] Audit every inventoried action against `UX_GUARDRAILS.md` §6 and §7; no interaction waits silently or loses its state on navigation/reconnect.
   4. [ ] [Agent] Confirm every endpoint, operation, field, and tool is represented in [`agent_surfaces.md`](../../reference/agent_surfaces.md) and the generated gate is clean.
   5. [ ] [Agent] Run `docker compose run --rm web mix precommit` and production asset/container builds.

5. [ ] **Guided product pass**
   1. [ ] [Guided] Exercise the product with two accounts and multiple windows while observing pending and remote state.
      1. [ ] [Guided] Create, edit, restructure, and filter.
      2. [ ] [Guided] Comment and manage members.
      3. [ ] [Guided] Navigate, disconnect, reload, and recover.
   2. [ ] [Guided] Read the load/capacity report together and identify the supported envelope, safety margin, limiting resource, and signals that future growth is approaching it.
   3. [ ] [Human] Complete the whole-product experience pass.
      1. [ ] [Human] Check desktop/narrow and keyboard/touch use.
      2. [ ] [Human] Check light/dark and reduced-motion presentation.
      3. [ ] [Human] Check button recognition and error copy.
      4. [ ] [Human] Check recovery confidence.

6. [ ] **Close-out**
   1. [ ] Resolve or explicitly rehome every omission found during the full pass; none remain as an unowned note in a closed arc.
   2. [ ] Update milestone status, PLAN, completion date, and CHANGELOG only after all acceptance criteria and guided checks pass.
   3. [ ] Record the next measured capacity trigger and the exact command future work uses to detect it.

## Exit

One client-rendered product remains, its failure and capacity boundaries are known, and M05 can add features without rebuilding them across two frontend architectures.
