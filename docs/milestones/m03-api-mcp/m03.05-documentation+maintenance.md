# m03.05 — Documentation & maintenance

_Parent: [`m03-api-mcp.md`](m03-api-mcp.md)_

Two files. `docs/specs/agent_integration.md` keeps the promises; `docs/reference/agent_surfaces.md` documents the HTTP API, the MCP server, and the scripted client that keep them. Written for the operator and their agents, not published to the web. Motivated by a stale example that cost a debugging session (`progress` vs `manual_progress`): the contract is only as trustworthy as the docs describing it, and docs nobody maintains rot silently.

**Plain English, few words — tables included.** Prose stays under 800 words per file, hand-written words only. A table gets one row per thing and the fewest columns that answer a real question — no column restating another, no sentences inside cells. A table's length comes from how many things exist, never from how they are described.

**The approach.** Anything mechanical is generated from the code and gated by a test, so it cannot go stale. Anything that needs a human voice — setup, walkthroughs, the why — is hand-written, and only that part relies on care. The generator and the drift guard are one mechanism: the generated text is committed, and a test regenerates it and compares. A stale doc fails the suite.

This arc runs last and then continuously. Public documentation waits for the milestone that exposes the API publicly.

9. [x] **Close what the API drive found.**

	From driving a live Initiative using only `agent_surfaces.md` (item 8.2.1). Everything the file documents matched. These are the things it doesn't document at all.

	1. [x] **Add 422 to the Errors table.** Every envelope rejection returns it — unknown lid, over the cap, a field the op doesn't accept.
	2. [x] **Document the per-op result shape.** `results[]` carries a per-index `status` of `ok`, `error`, or `not_applied`, and a `pointer` naming the offending field.
	3. [x] **Name the comments endpoint.** `GET /api/v1/initiatives/:id/tasks/:task_id/comments`. The `comment` shape is listed with no path that reaches it.
	4. [x] **Document the three absent endpoints.**
		1. [x] `GET /api/v1/me`.
		2. [x] `GET /api/v1/initiatives/:id/task_count`.
		3. [x] `POST /api/v1/imports` — what the scripted client's `import` verb posts to.
	5. [x] **Settle `manual_progress` on a parent.** The API accepts and stores it; the roll-up ignores it. Either refuse it or say plainly that it is ignored.
	6. [x] **Say a 429 carries `Retry-After`.** The table says wait; the header says how long.
	7. [x] **Exercise 403.** Needs an Initiative with AI access on where the token holder is not the owner.
	8. [x] **Stop advertising `owner_id` on `update initiative`.** The generated op table lists it; the op always refuses it as irreversible. An accepted key that never works is worse than an absent one.
	9. [x] **Say which shell's block to take.** The Setup line named the client but not the shell, so a reader with two blocks in front of them had only the fence language to go on.
	10. [x] **Say the connect blocks appear only just after minting.** The page shows them with a fresh token; the old wording read as though they were always there.
	11. [x] **Write the token before connecting.** `hermes mcp add` connects and reads the env file immediately, so the append had to come first in both Hermes variants.
	12. [x] **Point the PowerShell Hermes block at the Windows path.** It wrote `~/.hermes/.env`; Hermes on Windows reads `%LOCALAPPDATA%\hermes\.env`, so a good token landed where nothing read it.
	13. [x] **Default the account page's shell tabs to PowerShell.** PowerShell aliases `echo` and runs the POSIX line, then writes UTF-16 and fails silently; bash rejects `Add-Content` outright. The loud failure is the safer default.
	14. [x] **Give the MCP section its own walkthrough.** The Walkthrough under that heading is `doitlist.py` commands, which an MCP client never runs. Either move it under Scripted client or write one in tool calls.
	15. [x] **Drop "apply by the preview's id" from the walkthrough.** `--preview` prints no id and `import` has no apply flag; re-running without `--preview` is the real path.
	16. [x] **Make the mirror completion line work as written.** `done --mirror` needs an Initiative link the import never writes, so the walkthrough's command fails. The walkthrough passes `--initiative`; writing the URL into the mirror would break the import's byte-for-byte fidelity promise.
	17. [x] **Show where a record's id goes.** The envelope example is all `add` ops, so nothing in the file says an `update` or `remove` carries its target id beside `op` and `type`, not inside `data`. An agent working from the file alone put it in `data` and got a 422.
