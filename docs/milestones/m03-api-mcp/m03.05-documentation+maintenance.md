# m03.05 — Documentation & maintenance

_Parent: [`m03-api-mcp.md`](m03-api-mcp.md)_

_Status: **Approved — in progress.**_

Two files. `docs/specs/agent_integration.md` keeps the promises; `docs/reference/agent_surfaces.md` documents the HTTP API, the MCP server, and the scripted client that keep them. Written for the operator and their agents, not published to the web. Motivated by a stale example that cost a debugging session (`progress` vs `manual_progress`): the contract is only as trustworthy as the docs describing it, and docs nobody maintains rot silently.

**Plain English, few words — tables included.** Prose stays under 800 words per file, hand-written words only. A table gets one row per thing and the fewest columns that answer a real question — no column restating another, no sentences inside cells. A table's length comes from how many things exist, never from how they are described.

**The approach.** Anything mechanical is generated from the code and gated by a test, so it cannot go stale. Anything that needs a human voice — setup, walkthroughs, the why — is hand-written, and only that part relies on care. The generator and the drift guard are one mechanism: the generated text is committed, and a test regenerates it and compares. A stale doc fails the suite.

This arc runs last and then continuously. Public documentation waits for the milestone that exposes the API publicly.
