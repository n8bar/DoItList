# m03.04 — MCP, scripted client & companion skill

_Parent: [`m03-api-mcp.md`](m03-api-mcp.md)_

_Status: **Scope approved — implementation pending.**_

Arc 4 implements the [Agent Integration specification](../../specs/agent_integration.md) with one deterministic API parser, an MCP chat lane, and a standalone scripted client.

		5. [x] Use prose as the Task description only when it adds to the title.

	2. [x] **Map source numbering to index styles.**

		2. [x] Map mixed paths such as `I.A.2` to `outline`.
		3. [x] Map `I` and `II` to `roman`.
		4. [x] Map `A` and `B` to `alphabetical`.
		5. [x] Map plain bullets to `none`.
		6. [x] Set the detected style when creating an Initiative.
		7. [x] Default to `numerical` when source numbering is present but unrecognized or ambiguous.
	3. [x] **Add `POST /api/v1/imports`.**

		4. [x] In apply mode, run parsed operations through the existing pipeline in cap-sized batches, one transaction per batch.

	4. [x] **Record the import source once.** Add a comment to the imported root naming the supplied filename, or "pasted text" when none is supplied.
	5. [x] **Add import diffing to preview mode.**
		1. [x] Compare the source document with the live tree at an existing target.
		2. [x] Report missing and extra Tasks, completion mismatches, and order mismatches.
		3. [x] Write nothing.
	6. [x] **Preserve oversized source content.**
		1. [x] Keep Task titles within 200 characters; put remaining source detail in the description.
		2. [x] Set an import-size limit and allow any accepted item to fit in one description.
		3. [x] Reject over-limit imports before writing; never truncate content or invent Tasks.
	7. [x] **Test the parser and endpoint.**
		1. [x] Fixture a purpose-built large nested plan, `PLAN.md`, a chores list, a typed list, and a list with an embedded instruction.

4. [x] **Standalone scripted client.**

	1. [x] **Build the client foundation.**
		1. [x] Add `skills/doitlist/scripts/doitlist.py` using only the Python 3 standard library.
		2. [x] Keep import parsing in the API; the client handles requests, response formatting, and local completion mirroring.
		3. [x] Require `DOITLIST_API_URL` and `DOITLIST_API_TOKEN` from the environment, as emitted by the connect panel; report missing configuration without a fallback service URL.
		4. [x] Run on the agent's machine without the app container.
		5. [x] Use IDs in API requests and labels in operator output.
		6. [x] Require HTTPS except on loopback; refuse redirects and keep tokens out of output and saved responses.
		7. [x] Test missing configuration, URL validation, redirect refusal, and token redaction.
	2. [x] **Read verbs.**
		1. [x] Make `list` print the name and URL of each Initiative.
		2. [x] Add `tree <initiative> [--under <task>] [--depth n]`; scope output to the selected Task and descendants, with depth relative to that root.
		3. [x] Print an indented outline with label, id, title, Progress, done mark, and branch/leaf status under the [tree-visibility standard](../../specs/agent_integration.md#shared-work). Identify the displayed scope and depth limit; use API Progress and branch/leaf values without deriving them from visible rows.
		4. [x] Make `comments <task>` and `activity <initiative>` print compact text with author, time, and content; omit API envelope fields.
		5. [x] Test subtree and depth selection, completed-Task visibility, and unchanged Progress and branch/leaf status when descendants are outside the displayed scope.
	3. [x] **Write verbs.**
		1. [x] Add `add <parent> "title"`, `done <task>`, `progress <task> <n>`, `move <task> <new-parent> [position]`, `comment <task> "text"`, `retitle <task> "title"`, and `describe <task> "text"`.
		2. [x] Have the client read current state and submit each command as a one-op batch through the operations endpoint with `expected_version` from that read.
		3. [x] Validate arguments before sending; report invalid values without silently rewriting supplied content.
		4. [x] Persist each submitted request and its generated idempotency key without credentials; reuse both for retries after an unknown outcome. Honor `Retry-After` and report unresolved outcomes without claiming success.
		5. [x] On a version conflict, return the current record for reassessment; do not automatically resubmit with its newer version.
		6. [x] Test validation, version conflicts, lost responses, and retry identity in the CLI suite.
	4. [x] **Import and diff.** `import <file> [--into <initiative>] [--under <task>] [--preview]` posts the file's text to the imports endpoint and prints its summary; `diff <file> <initiative>` is the preview against an existing target. A plan with sub-documents is the agent's composition, one import per file.
	5. [x] **Support Linux and Windows.**

		2. [x] On Windows/PowerShell, run the same script with `py -3` or `python`; add the same environment variables and a matching version check to the PowerShell paste.
	6. [x] **Tests under `mix test`.** `python3` added to the Dockerfile; one ExUnit test runs the script's unittest suite — argument parsing, request shapes, outline rendering — and asserts a clean exit, so `mix test` stays the only gate.
	7. [x] **Add completion mirroring** under the [specified standard](../../specs/agent_integration.md#completion-mirroring).
		1. [x] Extend `done <task>` with `--mirror <file> --section <heading>` to complete and mirror one Task in one invocation.
		2. [x] Before writing, read the live tree and resolve exactly one matching checkbox within the named section; reject missing or ambiguous matches without fuzzy title matching.
		3. [x] Reuse §4.3's live read, conditional write, and retry state; after confirmed completion, update the checkbox while protecting concurrent file edits and preserving other content.
		4. [x] Record mirror recovery details before writing. Report each update's outcome; resume pending work after checking current state, and treat completion after reopening as a new operation.
		5. [x] Print a compact completion result and the next unfinished leaf in section order, or none, using the preceding live read with the confirmed completion applied; keep the normal path to one GET and one POST.
		6. [x] Test unique matching, concurrent live and file edits, interrupted writes, retries, reopening, and next-Task selection in the CLI suite on both supported platforms.
	8. [x] **Keep command results compact.**

		2. [x] Offer `--out <file>` to save the full API response without printing JSON to the terminal; print the saved path alongside the normal result.

6. [ ] **Omissions & Corrections**

	1. [x] **Preserve deep links through login.** Opening an Initiative URL while logged out currently lands on the Initiative list after login because authentication discards the requested path.
		1. [x] Store the requested path when the authentication plug redirects an unauthenticated GET; halted LiveView mounts pass it to the login page for storage.
		2. [x] `log_in_user` carries the stored path across session renewal and redirects to it only when local. Otherwise it uses the Initiative list; reject fully qualified and scheme-relative URLs.
		3. [x] Test logged-out Initiative URL → login → same Initiative, plain login → Initiative list, and fully qualified or scheme-relative stored URL → Initiative list.

	2. [x] **Support typed `%` references across index styles.** The tokenizer currently accepts only numerical labels; outline, roman, and alphabetical references stay literal.
		1. [x] Expand the typed-path matcher to roman, alphabetical, and numerical segments, resolve candidates through the live label map, and leave unresolved candidates literal.
		2. [x] Test that outline (`%I.A.2`, `%III`), roman, alphabetical, and numerical labels resolve to the correct `%<id>` while plain words after `%` remain literal.

	3. [x] **Exclude deleted Tasks from Initiative activity.** Events from soft-deleted Tasks, including comment events, currently appear in the workspace pane, API, and MCP resource even though readers cannot open those Tasks.
		1. [x] Filter the shared Initiative activity query to reader-visible Tasks so all three surfaces hide deleted-Task events and restored Tasks regain their history. Leave retention and hard deletion to M05 Trash.
		2. [x] Test that deleting a Task hides its events on all three surfaces, restoring it returns them, and live-Task events are unchanged.

	4. [x] **Reject positional numbering in agent-written titles.** Indices supply numbering; a title carrying its own duplicates it.
		1. [x] In `DoItWeb.Api.Operations`, fail `add task` and `update task` with a 422 (`pointer: "title"`) when the Initiative's `index_style` is not `none` and the title opens with `1.`, `2.3`, `4)`, `I.`, or `A)` followed by a space. Message: "Titles carry no positional numbering; the Initiative's index supplies it. Retry without the prefix, or pass `numbered_title: true` if the user asked for it."
		2. [x] Accept `numbered_title: true` in the op's `data` as the override; strip it before the changeset.
		3. [x] Add `--numbered` to the CLI's `add` and `retitle`; MCP clients pass the flag through `apply_operations` data.
		4. [x] Test both lanes: refused under `numerical`, accepted under `none`, accepted under `numerical` with the override; "A big task" and "I want this" pass; `--numbered` sends the flag.

	5. [x] **Show the Initiative's unit count.** Branches show their leaf count; the Initiative shows none, though its count is the root task's.
		1. [x] Compute it as the root's `branch_unit_count`: descendant leaves under `leaf_average`, top-level Tasks under `single_level`.
		2. [x] Show it in the workspace header with the same badge and title the branch rows use.
		3. [x] Add `unit_count` to the API's Initiative summary and tree root; the MCP list and tree tools pass it through.
		4. [x] Print it on the CLI `tree` header line.
		5. [x] Test the two calc modes, the header badge, the API field, and the CLI line.

	6. [x] **Accept the stored reference form in the CLI.** Task fields store references as `%<272>` with literal brackets, but the CLI accepts only `272` and `%272`, so the skill's one naming form fails at the command line.
		1. [x] Extend `parse_task_ref` and the parent parser to accept `%<id>` alongside the existing forms.
		2. [x] Test that `%<272>`, `%272`, and `272` resolve to the same Task and that `%<abc>` is refused with the existing usage error.

	7. [x] **Apply a preview without resending the source.** In the chat lane a preview followed by the import makes the agent emit the whole document twice.
		1. [x] Preview responses from the imports endpoint return a `preview_id`. The server keeps the latest preview per access token and target (Initiative, or "new" for a fresh Initiative) with its source text, target, and the target Initiative's version; a newer preview replaces it; unapplied previews expire after 1 hour.
		2. [x] The imports endpoint accepts `preview_id` in place of `text` and applies the stored source to the stored target. An unknown or expired id is refused with an actionable message; a target whose version moved since the preview gets the standard stale-write reply with the current record. Applying consumes the preview.
		3. [x] `import_text` accepts `preview_id` instead of `text`, and its preview reply surfaces the id; the CLI is unchanged, since the script rereads the file at no cost to the agent.
		4. [x] Test that preview then apply-by-id builds the same tree as a direct import, that a stale target and an unknown or expired id are refused, that a second preview replaces the first, and that a second apply of the same id is refused.

	8. [ ] **Fall back when the pending store is unwritable.** Sandboxed agents cannot create `~/.doitlist/state`, so every mirrored write dies in a traceback before it starts.
		1. [ ] When the default state directory cannot be created or written, use `.doitlist/state` under the current directory instead, and say so on the first use.
		2. [ ] When neither is writable, refuse before any request with one line naming `DOITLIST_STATE_DIR` as the fix; never a traceback.
		3. [ ] Test the fallback, the refusal, and that the pending record for a fallback-stored write is found by `retry`.

## Optional / Future

- A web import UI for pasting or uploading large documents through the same endpoint without an agent.

## Non-goals

- General two-way sync between Markdown and an Initiative beyond explicit completion mirroring. Imports are one-shot; diffs are read-only.
- Hosted chat clients connecting to the MCP; public exposure, standards-compliant OAuth, and long-document relay are M06 scope.
