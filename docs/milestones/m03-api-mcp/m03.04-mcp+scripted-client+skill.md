# m03.04 — MCP, scripted client & companion skill

_Parent: [`m03-api-mcp.md`](m03-api-mcp.md)_

_Status: **Scope approved — implementation pending.**_

Arc 4 implements the [Agent Integration specification](../../specs/agent_integration.md) with one deterministic API parser, an MCP chat lane, and a standalone scripted client.

1. [x] **Turn the import ceremony off.**
	1. [x] Default the gate to off; make off suppress first-import declarations, content-shape refusals, approval parking, and single-create pauses.
	2. [x] Remove the README's large-import gating paragraph; while the gate is off, hide the account page's import-approval controls and cards.
	3. [x] Keep the ceremony's existing tests passing with the gate explicitly on; add one test that an unannounced large batch and a single create pass with it off.

2. [x] **Import parser and endpoint.**
	1. [x] **Build the pure, dependency-free parser.** Text → manifest → operations.
		1. [x] Parse Markdown headings as branches and bulleted or numbered lists, with or without checkboxes, as Tasks.
		2. [x] Derive nesting from spaces or tabs.
		3. [x] Preserve source order.
		4. [x] Map checked items to `done: true`.
		5. [x] Use prose as the Task description only when it adds to the title.
		6. [x] Map the top heading to the target Initiative or Task, never a wrapper Task.
		7. [x] Unit-test every supported form and mapping rule.
	2. [x] **Map source numbering to index styles.**
		1. [x] Map `1.` and `M1` to `numerical`.
		2. [x] Map mixed paths such as `I.A.2` to `outline`.
		3. [x] Map `I` and `II` to `roman`.
		4. [x] Map `A` and `B` to `alphabetical`.
		5. [x] Map plain bullets to `none`.
		6. [x] Set the detected style when creating an Initiative.
		7. [x] Default to `numerical` when source numbering is present but unrecognized or ambiguous.
	3. [x] **Add `POST /api/v1/imports`.**
		1. [x] Accept source text, a target, and `preview`.
		2. [x] Allow either a new Initiative name or an existing Initiative with an optional parent Task as the target.
		3. [x] In preview mode, return the labeled outline, counts for items, done items, and depth, and the detected style; write nothing.
		4. [x] In apply mode, run parsed operations through the existing pipeline in cap-sized batches, one transaction per batch.
		5. [x] Make apply idempotent by source-text hash per target.
		6. [x] Return the preview summary plus the Initiative URL.
	4. [x] **Record the import source once.** Add a comment to the imported root naming the supplied filename, or "pasted text" when none is supplied.
	5. [x] **Add import diffing to preview mode.**
		1. [x] Compare the source document with the live tree at an existing target.
		2. [x] Report missing and extra Tasks, completion mismatches, and order mismatches.
		3. [x] Write nothing.
	6. [x] **Preserve oversized source content.**
		1. [x] Keep Task titles within 200 characters; put remaining source detail in the description.
		2. [x] Set an import-size limit and allow any accepted item to fit in one description.
		3. [x] Reject over-limit imports before writing; never truncate content or invent Tasks.
	7. [x] **Test the parser and endpoint.**
		1. [x] Fixture a purpose-built large nested plan, `PLAN.md`, a chores list, a typed list, and a list with an embedded instruction.
		2. [x] Pin counts, order, depth, completion, descriptions, and style.
		3. [x] Verify preview is read-only, repeat apply is a no-op, and batching preserves parent-child relationships through local IDs.
		4. [x] Verify embedded instructions import verbatim without execution.
		5. [x] Verify overflow is preserved and rejection writes nothing.

4. [ ] **Standalone scripted client.**

	1. [ ] **Build the client foundation.**
		1. [ ] Add `skills/doitlist/scripts/doitlist.py` using only the Python 3 standard library.
		2. [ ] Keep import parsing in the API; the client handles requests, response formatting, and local completion mirroring.
		3. [ ] Require `DOITLIST_API_URL` and `DOITLIST_API_TOKEN` from the environment, as emitted by the connect panel; report missing configuration without a fallback service URL.
		4. [ ] Run on the agent's machine without the app container.
		5. [ ] Use IDs in API requests and labels in operator output.
		6. [ ] Require HTTPS except on loopback; refuse redirects and keep tokens out of output and saved responses.
		7. [ ] Test missing configuration, URL validation, redirect refusal, and token redaction.
	2. [ ] **Read verbs.**
		1. [ ] Make `list` print the name and URL of each Initiative.
		2. [ ] Add `tree <initiative> [--under <task>] [--depth n]`; scope output to the selected Task and descendants, with depth relative to that root.
		3. [ ] Print an indented outline with label, id, title, Progress, done mark, and branch/leaf status under the [tree-visibility standard](../../specs/agent_integration.md#shared-work). Identify the displayed scope and depth limit; use API Progress and branch/leaf values without deriving them from visible rows.
		4. [ ] Make `comments <task>` and `activity <initiative>` print compact text with author, time, and content; omit API envelope fields.
		5. [ ] Test subtree and depth selection, completed-Task visibility, and unchanged Progress and branch/leaf status when descendants are outside the displayed scope.
	3. [ ] **Write verbs.**
		1. [ ] Add `add <parent> "title"`, `done <task>`, `progress <task> <n>`, `move <task> <new-parent> [position]`, `comment <task> "text"`, `retitle <task> "title"`, and `describe <task> "text"`.
		2. [ ] Have the client read current state and submit each command as a one-op batch through the operations endpoint with `expected_version` from that read.
		3. [ ] Validate arguments before sending; report invalid values without silently rewriting supplied content.
		4. [ ] Persist each submitted request and its generated idempotency key without credentials; reuse both for retries after an unknown outcome. Honor `Retry-After` and report unresolved outcomes without claiming success.
		5. [ ] On a version conflict, return the current record for reassessment; do not automatically resubmit with its newer version.
		6. [ ] Test validation, version conflicts, lost responses, and retry identity in the CLI suite.
	4. [ ] **Import and diff.** `import <file> [--into <initiative>] [--under <task>] [--preview]` posts the file's text to the imports endpoint and prints its summary; `diff <file> <initiative>` is the preview against an existing target. A plan with sub-documents is the agent's composition, one import per file.
	5. [ ] **Support Linux and Windows.**
		1. [ ] On Linux/POSIX, run with `python3`; add `DOITLIST_API_URL`, `DOITLIST_API_TOKEN`, and a `python3 --version` check to the POSIX connect paste.
		2. [ ] On Windows/PowerShell, run the same script with `py -3` or `python`; add the same environment variables and a matching version check to the PowerShell paste.
	6. [ ] **Tests under `mix test`.** `python3` added to the Dockerfile; one ExUnit test runs the script's unittest suite — argument parsing, request shapes, outline rendering — and asserts a clean exit, so `mix test` stays the only gate.
	7. [ ] **Add completion mirroring** under the [specified standard](../../specs/agent_integration.md#completion-mirroring).
		1. [ ] Extend `done <task>` with `--mirror <file> --section <heading>` to complete and mirror one Task in one invocation.
		2. [ ] Before writing, read the live tree and resolve exactly one matching checkbox within the named section; reject missing or ambiguous matches without fuzzy title matching.
		3. [ ] Reuse §4.3's live read, conditional write, and retry state; after confirmed completion, update the checkbox while protecting concurrent file edits and preserving other content.
		4. [ ] Record mirror recovery details before writing. Report each update's outcome; resume pending work after checking current state, and treat completion after reopening as a new operation.
		5. [ ] Print a compact completion result and the next unfinished leaf in section order, or none, using the preceding live read with the confirmed completion applied; keep the normal path to one GET and one POST.
		6. [ ] Test unique matching, concurrent live and file edits, interrupted writes, retries, reopening, and next-Task selection in the CLI suite on both supported platforms.
	8. [ ] **Keep command results compact.**
		1. [ ] Print write outcomes and affected Task references; on failure, include actionable per-operation errors rather than only the top-level message.
		2. [ ] Offer `--out <file>` to save the full API response without printing JSON to the terminal; print the saved path alongside the normal result.
		3. [ ] Test success and failure summaries and saved responses; ensure compact output preserves errors and requested content.

6. [ ] **Omissions & Corrections**

	1. [ ] **Preserve deep links through login.** Opening an Initiative URL while logged out currently lands on the Initiative list after login because authentication discards the requested path.
		1. [ ] Store the requested path when the authentication plug redirects an unauthenticated GET; halted LiveView mounts pass it to the login page for storage.
		2. [ ] `log_in_user` carries the stored path across session renewal and redirects to it only when local. Otherwise it uses the Initiative list; reject fully qualified and scheme-relative URLs.
		3. [ ] Test logged-out Initiative URL → login → same Initiative, plain login → Initiative list, and fully qualified or scheme-relative stored URL → Initiative list.

	2. [ ] **Support typed `%` references across index styles.** The tokenizer currently accepts only numerical labels; outline, roman, and alphabetical references stay literal.
		1. [ ] Expand the typed-path matcher to roman, alphabetical, and numerical segments, resolve candidates through the live label map, and leave unresolved candidates literal.
		2. [ ] Test that outline (`%I.A.2`, `%III`), roman, alphabetical, and numerical labels resolve to the correct `%<id>` while plain words after `%` remain literal.

	3. [ ] **Exclude deleted Tasks from Initiative activity.** Events from soft-deleted Tasks, including comment events, currently appear in the workspace pane, API, and MCP resource even though readers cannot open those Tasks.
		1. [ ] Filter the shared Initiative activity query to reader-visible Tasks so all three surfaces hide deleted-Task events and restored Tasks regain their history. Leave retention and hard deletion to M05 Trash.
		2. [ ] Test that deleting a Task hides its events on all three surfaces, restoring it returns them, and live-Task events are unchanged.

## Optional / Future

- A web import UI for pasting or uploading large documents through the same endpoint without an agent.

## Non-goals

- General two-way sync between Markdown and an Initiative beyond explicit completion mirroring. Imports are one-shot; diffs are read-only.
- Hosted chat clients connecting to the MCP; public exposure, standards-compliant OAuth, and long-document relay are M06 scope.
